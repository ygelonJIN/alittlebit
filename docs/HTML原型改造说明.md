# HTML 原型改造说明

## 1. 文档目的

本文档定义当前 `ide-md-chat.html` 原型页如何从“静态预览页”演进为“可反复验证的结构原型”。它回答的是：

- 当前 HTML 该保留什么
- 当前 HTML 该改什么
- 当前 HTML 该如何作为正式开发前的验证层
- 如何避免把原型页直接当正式实现用

---

## 2. 原型页定位

当前 HTML 原型页的职责只有三个：

1. 验证布局
2. 验证视觉语言
3. 验证基础交互状态

它不负责：
- 最终组件化架构
- 复杂状态管理
- 最终版本系统
- 最终文档治理逻辑

---

## 3. 当前 HTML 需要保留的内容

### 3.1 必须保留

- 顶部版本栏
- 左侧文件栏
- 中间编辑器
- 右侧 Chat 面板
- 基础暗色主题
- 基础分栏结构
- 当前已有的内容样例

### 3.2 建议保留但可后续替换

- 静态占位数据
- 示例文档内容
- 示例消息流
- 示例版本项
- 示例状态标签

### 3.3 不要急着删的原因

这些内容虽然未必是最终形态，但对快速验证结构和视觉一致性很有价值。只要体量不大，就先保留，后续再逐步替换成真实数据。

---

## 4. 当前 HTML 需要改造的内容

### 4.1 样式层

- 统一颜色变量
- 统一间距变量
- 统一圆角变量
- 统一边框变量
- 统一字号和行高

### 4.2 结构层

- 把重复区域抽成可复用块
- 把左中右三栏职责明确化
- 把顶部版本栏从普通标签视觉改成版本带视觉

### 4.3 交互层

- 编辑区当前行高亮必须稳定
- Chat 面板输入区与消息区要有清晰边界
- 文件栏选中态要明确
- 版本栏选中态要稳定

---

## 5. 原型页与正式实现的边界

### 5.1 原型页能做的事

- 快速改布局
- 快速改颜色
- 快速看页面整体效果
- 快速观察编辑器、版本栏、Chat 的相对关系

### 5.2 原型页不该做的事

- 不该堆所有业务逻辑
- 不该承载复杂状态同步
- 不该直接写死大量历史数据和版本逻辑
- 不该长期以绝对定位模拟编辑器真实行为

---

## 6. 原型页改造顺序

### 第一步：统一视觉系统

先把页面的颜色、边框、间距、字号和圆角统一起来。

### 第二步：明确四个区域

- 顶部版本栏
- 左侧文件栏
- 中间编辑器
- 右侧 Chat 面板

### 第三步：修复编辑器行级表现

- 当前行高亮必须和文本绑定
- 行号与文本对齐
- 滚动后高亮不丢

### 第四步：把静态数据变成配置数据

- 文件列表改为数据驱动
- 版本项改为数据驱动
- 消息流改为数据驱动
- 文本内容改为数据驱动

### 第五步：准备组件化拆分

- 页面头部独立
- 文件栏独立
- 编辑器独立
- Chat 独立

---

## 7. 推荐的原型数据结构

### 7.1 文件列表

```ts
interface FileItem {
  id: string;
  name: string;
  type: 'md' | 'folder' | 'json' | 'log' | 'diff';
  active?: boolean;
  status?: 'normal' | 'frozen' | 'draft';
}
```

### 7.2 版本项

```ts
interface VersionItem {
  id: string;
  title: string;
  status: 'draft' | 'refining' | 'confirmed' | 'frozen';
  active?: boolean;
}
```

### 7.3 消息项

```ts
interface ChatMessage {
  id: string;
  role: 'user' | 'assistant';
  content: string;
  timestamp?: string;
}
```

### 7.4 编辑器行

```ts
interface EditorLine {
  id: string;
  lineNumber: number;
  text: string;
  active?: boolean;
}
```

---

## 8. 原型页视觉原则

- 低噪音
- 高一致性
- 低装饰
- 高可读性
- 清晰的模块边界

页面看起来应该像一个专注的工作台，而不是普通网页拼接。

---

## 9. 与正式开发的衔接方式

原型页要为正式开发提供以下价值：

1. 验证布局比例
2. 验证视觉主题
3. 验证编辑器高亮方式
4. 验证 Chat 区信息密度
5. 验证版本栏和文件栏节奏

当这些验证完成后，就可以从原型页迁移到组件化实现。

---

## 10. 验收标准

原型页重构完成后，应该满足：

- 页面结构稳定
- 样式统一
- 编辑器当前行稳定
- Chat 面板不过分抢眼
- 文件栏和版本栏职责清楚
- 后续可以平滑拆成组件

---

## 11. 结论

当前 HTML 的正确角色是“原型验证层”，不是“最终实现层”。

先把它改对、改稳、改统一，再进入真正的组件化和业务化开发。
