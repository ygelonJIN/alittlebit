# Chat 面板重构方案

## 1. 文档目的

本文档定义右侧 Chat 面板如何从原型态重构为一个克制、稳定、服务于文档推进的 AI 协作面板。

本文档重点回答：
- Chat 面板的职责是什么
- 需要保留什么
- 需要改成什么样
- 如何避免它抢走主编辑器的视觉权重

---

## 2. 面板定位

Chat 面板不是独立聊天产品，而是文档工作台里的辅助协作区。

它的唯一核心使命是：

- 围绕当前文档发问
- 收敛需求和版本
- 辅助整理变更
- 辅助生成下一步行动
- 辅助冻结和归档

---

## 3. 现状问题

当前 Chat 面板常见问题是：

1. 视觉太像普通聊天 App。
2. 气泡样式容易太重。
3. 输入区和消息区不够统一。
4. 容易抢主视觉，影响中间编辑器。
5. 与文档上下文的关联感还不够强。

---

## 4. 重构目标

### 4.1 视觉目标

- 克制。
- 稳定。
- 与整体 IDE 工作台风格一致。
- 不要比编辑器更抢眼。

### 4.2 交互目标

- 消息流清晰。
- 输入区明确。
- 发送行为明确。
- 能表达上下文、确认和建议。

### 4.3 产品目标

- Chat 服务文档推进。
- Chat 服务版本治理。
- Chat 服务确认流程。

---

## 5. 结构设计

### 5.1 推荐层级

建议把 Chat 面板拆成以下层级：

1. `chat-shell`
2. `chat-header`
3. `chat-context`
4. `chat-message-list`
5. `chat-message`
6. `chat-message--assistant`
7. `chat-message--user`
8. `chat-input`
9. `chat-input-toolbar`
10. `chat-send-button`

### 5.2 各层职责

#### `chat-shell`
- 承载整个面板。
- 负责背景、边界、整体尺寸。

#### `chat-header`
- 显示当前 Chat 的角色或状态。
- 可显示“AI Assist / Context / Version”。

#### `chat-context`
- 展示当前上下文摘要。
- 用于提醒正在处理哪个文档、哪个版本。

#### `chat-message-list`
- 承载消息流。
- 支持滚动。

#### `chat-message`
- 消息单元。
- 控制颜色、边距、密度。

#### `chat-input`
- 输入区域。
- 允许输入问题、指令、确认内容。

#### `chat-input-toolbar`
- 附加快捷操作。
- 如发送、清空、插入上下文等。

---

## 6. 消息样式规则

### 6.1 assistant 消息

- 使用更克制的背景。
- 文本对比度清晰即可，不要过度高亮。
- 内容以总结、建议、判断为主。

### 6.2 user 消息

- 颜色可以略微更明确。
- 但不要像通用社交聊天那样夸张。
- 以“指令”和“确认”为主。

### 6.3 气泡密度

- 气泡圆角不要过大。
- 留白不要过多。
- 消息间距适中。
- 整体像工具面板，不像社交应用。

---

## 7. 输入区规则

### 7.1 输入框职责

输入框只负责：
- 输入问题
- 输入确认
- 输入修订指令
- 输入冻结指令

### 7.2 输入框样式

- 单行或多行输入都可以，但必须清楚表达输入焦点。
- 输入框边框要轻。
- 输入框背景和面板统一。
- 占位提示要简洁。

### 7.3 发送按钮

- 发送按钮必须明确可见。
- 不要过度装饰。
- 与输入框节奏统一。

---

## 8. 上下文感知规则

### 8.1 Chat 必须知道当前文档

Chat 面板应该在视觉上或结构上明确当前关联的文档、版本或任务。

### 8.2 Chat 必须知道当前阶段

例如：
- 需求收敛阶段
- 编辑器重构阶段
- 版本治理阶段
- 冻结阶段

### 8.3 Chat 不应孤立存在

它的输出必须和编辑器、版本栏、文件栏产生关联，而不是完全独立的闲聊区。

---

## 9. 推荐状态字段

```ts
interface ChatContext {
  documentName: string;
  version: string;
  stage: 'draft' | 'refining' | 'confirmed' | 'frozen';
  lastQuestion?: string;
  pendingItems?: string[];
}
```

---

## 10. 交互规则

### 10.1 默认行为

- 回车发送。
- Shift+Enter 换行。
- 消息列表自动滚到底部但不要打断用户阅读。

### 10.2 消息更新

- 新消息应明确标识是谁发的。
- AI 消息应尽可能结构化。
- 用户确认项和待确认项要显式列出。

### 10.3 清空/重置

- 允许清空当前对话。
- 但历史上下文如果进入版本系统，应保留摘要。

---

## 11. 与版本系统的联动

Chat 不只是聊天记录，而是版本治理流程的一部分。

它应支持：
- 版本推进建议
- 变更点确认
- 暂存项标记
- 冻结前检查
- 归档提醒

---

## 12. 当前阶段实现建议

### 12.1 先做视觉统一

- 统一气泡风格
- 统一面板背景
- 统一输入框样式

### 12.2 再做信息结构

- 加上下文区
- 加上当前阶段区
- 加上消息分组区

### 12.3 再做版本联动

- 显示当前文档名
- 显示当前版本号
- 显示当前阶段

---

## 13. 验收标准

Chat 面板重构完成后，应满足：

- 不抢中间编辑器视觉
- 消息风格统一
- 输入区清楚
- 上下文明确
- 可以服务文档推进，而不是独立闲聊

---

## 14. 结论

Chat 面板的重点不是“更像聊天”，而是“更像协作工具”。

它必须克制、准确、与文档联动。
