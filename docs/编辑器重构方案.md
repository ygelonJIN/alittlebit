# 编辑器重构方案

## 1. 文档目的

本文档定义中间编辑区如何从当前原型状态重构为一个真正稳定、可维护、可扩展的 Markdown 编辑器区域。本文档重点回答：

- 编辑器当前为什么不稳定
- 应该采用什么结构
- 如何修复选中行、滚动、高亮、行号和光标的对齐问题
- 如何让编辑器更接近真实 IDE 行为

---

## 2. 现状问题

当前编辑区存在以下问题：

1. 当前行高亮依赖静态覆盖层，不是真实行级绑定。
2. 滚动后高亮容易丢失或错位。
3. 行高、字号、padding 没有严格统一。
4. 中间区域更像静态展示，而不是真正的编辑器。
5. 顶部渐变与选中行逻辑耦合不清，导致视觉状态不稳定。

根因不是单纯 CSS 值不对，而是结构层设计不对。

---

## 3. 重构目标

### 3.1 视觉目标

- 看起来像真正的编辑器，而不是普通文本块。
- 行号、正文、当前行、光标有明确层次。
- 编辑器密度接近 VS Code 风格，但保持你自己的主题。

### 3.2 行为目标

- 当前行高亮必须和文本行绑定。
- 滚动后当前行仍应存在。
- 选中态不能随着视口变化而消失。
- 编辑器内部状态必须能持久表达。

### 3.3 维护目标

- 编辑器结构可拆分。
- 行渲染可数据化。
- 样式可复用。
- 后续能从静态页面迁移到组件化实现。

---

## 4. 编辑器结构设计

### 4.1 推荐层级

编辑器区域建议分为以下层级：

1. `editor-shell`
2. `editor-toolbar`
3. `editor-scroll`
4. `editor-gutter`
5. `editor-content`
6. `editor-line`
7. `editor-line--active`
8. `editor-caret`

### 4.2 结构职责

#### `editor-shell`
- 承载整个编辑器区域。
- 负责背景、边界、整体尺寸。

#### `editor-toolbar`
- 承载 Markdown / Auto Save / Frozen 状态。
- 承载 Ln / Col 等状态信息。

#### `editor-scroll`
- 负责滚动容器。
- 负责展示顶部渐变与滚动边界。

#### `editor-gutter`
- 负责行号显示。
- 行号必须和内容行一一对应。

#### `editor-content`
- 负责正文文本渲染。
- 每一行都是独立元素。

#### `editor-line`
- 文本行基础单元。
- 高亮、光标、状态都应该绑定在这一层。

#### `editor-line--active`
- 当前行样式。
- 必须是行级样式，不是浮层样式。

#### `editor-caret`
- 光标层。
- 仅在当前活动行内部展示。

---

## 5. 行渲染规则

### 5.1 行级绑定原则

每一行必须对应一个真实 DOM 节点或等价渲染单元。当前行高亮只能加在该节点上，不能在外层另外盖一层假装高亮。

### 5.2 当前行规则

- 当前行高亮必须使用行级 class。
- 当前行高亮不能脱离文本内容。
- 当前行的背景、边框、光标必须属于同一个行节点。

### 5.3 行高规则

- 行高必须统一。
- 行高要和字号、行内 padding、光标高度共同决定。
- 不允许高亮条和实际文本框高度不一致。

### 5.4 行号规则

- 行号高度与内容行高度一致。
- 行号与文本行垂直对齐。
- 行号不应因滚动独立漂移。

---

## 6. 滚动行为规则

### 6.1 顶部渐变

顶部渐变只负责“滚动存在感”，不负责当前行状态。

### 6.2 当前行稳定性

- 当编辑器滚动时，当前行高亮必须仍然存在。
- 当前行不能因为视口变化丢失。
- 选中状态应该跟随数据，不应该跟随固定坐标。

### 6.3 视口与行状态分离

- 视口变化只影响可见范围。
- 当前行状态由数据决定。
- 两者不能混淆。

---

## 7. 选中行实现规则

### 7.1 错误做法

以下做法不允许继续使用：

- 用一个绝对定位浮层模拟选中行
- 通过固定 top 值表达“当前行”
- 滚动后让高亮条停留在原位置

### 7.2 正确做法

- 在行数据里标记当前活动行。
- 渲染时给该行添加 active 状态。
- 高亮、光标、边框都直接作用于该行。

### 7.3 当前行状态字段建议

```ts
{
  lineNumber: number;
  text: string;
  active: boolean;
  selected: boolean;
}
```

---

## 8. 顶部渐变规则

顶部渐变只作为编辑器滚动时的视觉层次，不应参与选中逻辑。

规则：
- 渐变层固定挂在滚动容器顶部。
- 渐变层不拦截事件。
- 渐变层不影响当前行判定。

---

## 9. 编辑器内容组织建议

### 9.1 数据结构

编辑器内容建议按行数组组织，而不是按一整坨字符串直接硬塞到 DOM。

```ts
interface EditorLine {
  id: string;
  lineNumber: number;
  text: string;
  type?: 'heading' | 'paragraph' | 'list' | 'code' | 'quote' | 'meta';
  active?: boolean;
}
```

### 9.2 渲染方式

- 每行作为单独节点渲染。
- 每行可附加类型 class。
- 当前行独立高亮。
- 行号列和文本列同步渲染。

---

## 10. 样式统一要求

- 字号统一。
- 行高统一。
- 内边距统一。
- 高亮色统一。
- 当前行颜色必须比普通行略亮，但不能过饱和。
- 光标必须明显但克制。

---

## 11. 当前阶段实现建议

### 11.1 第一步

先把当前行从静态 overlay 改成行节点样式。

### 11.2 第二步

把行号和正文拆开，确保一行对应一个数据单元。

### 11.3 第三步

把滚动容器和顶部渐变分离。

### 11.4 第四步

再考虑更高级的 Markdown 语义渲染。

---

## 12. 验收标准

编辑器重构完成后，应满足：

- 当前行高亮不会在滚动后消失
- 行高和文本对齐
- 行号和正文一致
- 编辑区像真实编辑器
- 不依赖固定坐标伪造选中态

---

## 13. 结论

编辑器的关键不是“把颜色改对”，而是“把高亮和文本行绑定”。

只有结构正确，后续的视觉和交互抛光才有意义。
