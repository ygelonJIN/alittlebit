# 组件拆分与目录设计

## 1. 文档目的

本文档定义从当前原型页迁移到正式前端实现时，应该如何拆分组件、如何组织目录、如何避免逻辑和样式混乱。

---

## 2. 拆分目标

- 每个组件职责单一
- 每个模块能独立维护
- 样式和逻辑尽量分离
- 未来可以替换局部实现而不影响全局

---

## 3. 推荐组件列表

### 3.1 顶部版本栏组件

名称建议：`TopVersionBar`

职责：
- 显示版本列表
- 显示当前版本状态
- 支持版本切换
- 显示版本标题和辅助信息

### 3.2 左侧文件栏组件

名称建议：`FileExplorer`

职责：
- 显示文件树
- 展示文件状态
- 切换当前文件
- 预留文件夹、版本、日志、差异入口

### 3.3 中间编辑器组件

名称建议：`MarkdownEditor`

职责：
- 渲染 Markdown 原文
- 显示行号
- 显示当前行
- 支持滚动
- 展现编辑器核心视觉

### 3.4 右侧 Chat 组件

名称建议：`ChatPanel`

职责：
- 渲染消息流
- 渲染输入框
- 渲染上下文信息
- 支持发送消息

### 3.5 状态栏组件

名称建议：`StatusBar`

职责：
- 显示版本状态
- 显示文档状态
- 显示一些辅助提示

## 5. 拆分原则

### 5.1 一个组件一个职责

不要把版本栏、文件栏、编辑器、Chat 混在一个大组件里。

### 5.2 数据和视图分开

数据尽量从 `data/` 或状态层传入，不在组件内部硬编码。

### 5.3 样式和行为分离

- 样式放在独立 CSS 文件
- 行为逻辑放在组件 TS/JS 文件
- 公共变量统一放在 `variables.css`

### 5.4 先静态后动态

第一步可以静态渲染，第二步再接真实状态。

## 6. 数据目录设计

### 6.1 `versions.ts`

存放版本列表与版本状态。

### 6.2 `files.ts`

存放文件树、文件类型、文件状态。

### 6.3 `messages.ts`

存放 Chat 消息流。

### 6.4 `editorLines.ts`

存放编辑器行数据。

---

## 7. 公共样式目录设计

### 7.1 `variables.css`

建议放：
- 主题颜色
- 间距
- 圆角
- 字号
- 行高
- 边框色

### 7.2 `reset.css`

建议放基础重置和滚动条基础样式。

## 8. 组件接口建议

### 8.1 `TopVersionBar`

```ts
interface TopVersionBarProps {
  versions: VersionItem[];
  activeVersionId: string;
  onSelectVersion: (id: string) => void;
}
```

### 8.2 `FileExplorer`

```ts
interface FileExplorerProps {
  files: FileItem[];
  activeFileId: string;
  onSelectFile: (id: string) => void;
}
```

### 8.3 `MarkdownEditor`

```ts
interface MarkdownEditorProps {
  lines: EditorLine[];
  activeLineId: string;
}
```

### 8.4 `ChatPanel`

```ts
interface ChatPanelProps {
  messages: ChatMessage[];
  context: ChatContext;
  onSend: (text: string) => void;
}
```

## 9. 目录与版本体系的联动

组件目录不是单独存在的，它要和版本治理目录一起考虑：

- 版本目录存事实
- 组件目录存实现
- 数据目录存渲染数据
- 文档目录存规范

这样以后改产品，不会把实现和文档搅在一起。

---

## 10. 实施顺序

### 第一步
先拆样式变量。

### 第二步
再拆顶部、左侧、中间、右侧四个组件。

### 第三步
再拆数据文件。

### 第四步
再做状态管理和事件流。

### 第五步
再考虑更复杂的动态能力。

---

## 11. 验收标准

组件拆分完成后，应该满足：

- 结构清晰
- 文件职责明确
- 样式复用方便
- 后续局部重构不影响全局
- 组件能独立维护

---

## 12. 结论

组件拆分不是为了“拆得碎”，而是为了让整个 App 以后能稳定增长。

先有清晰目录，再有清晰组件，最后才有清晰功能。
