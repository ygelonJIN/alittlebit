# APP 改造总纲

## 1. 文档目的

本文档定义当前项目从“静态 IDE 风格页面”演进为“可持续开发的 AI 文档工作台 App”的总目标、边界、原则、阶段划分和交付标准。它是所有后续开发文档、产品文档、拆分文档、实现文档的总入口。

本文档不直接描述某个单点 UI 的具体样式实现，也不替代任务清单；它只定义“为什么做、做成什么样、做到什么程度算成功”。

---

## 2. 项目目标

### 2.1 最终产品形态

最终产品是一个以 Markdown 文档为中心的工作台 App，具备以下固定区域：

- 顶部版本栏
- 左侧文件栏 / Explorer
- 中间 Markdown 编辑区
- 右侧 AI Chat 面板
- 基础状态提示区（如需要）

### 2.2 核心能力

1. 文档编辑
   - 中间区域必须能承载 Markdown 原文编辑。
   - 编辑区应具备真实编辑器感，而不是简单的文本展示。

2. 文件组织
   - 左侧文件栏用于组织当前项目中的文档、版本、日志、差异文件、归档文件。
   - 文件栏要支持后续扩展，但当前阶段只保留必要能力。

3. 版本管理
   - 顶部版本栏用于表达当前版本、历史版本、冻结版本和派生版本。
   - 版本切换应清晰、统一、可识别。

4. AI 辅助
   - 右侧 AI Chat 面板用于围绕当前文档进行问答、确认、总结、版本推进。
   - Chat 必须服务于文档，不抢主视觉。

5. 文档治理
   - 支持版本摘要、变更记录、确认记录、问答记录、冻结摘要、归档索引。

## 3. 设计原则

### 3.1 先保留，再删减

- 体量不大、未来可能用上的东西先保留。
- 不盲目删除已有区域或已有信息结构。
- 只删除明确无用、长期不会恢复的部分。

### 3.2 先统一，再细化

- 顶部、左侧、中间、右侧必须先统一风格。
- 所有区域尽量复用同一套颜色、边框、圆角、层级、间距变量。
- 避免每个区域写一套不同规则。

### 3.3 先真实，再美化

- 编辑区必须先做到“真实编辑器感”。
- 选中行、滚动、行高、光标、行号必须稳定。
- 美化只能建立在真实交互成立之后。

### 3.4 先骨架，再交互

- 先把布局、区域、数据流、文件结构搭起来。
- 再做交互增强、快捷操作、差异查看、辅助提示。

### 3.5 先可用，再完善

- 第一目标是可用。
- 第二目标是好用。
- 第三目标是像一个成熟产品。

## 4. 现状判断

当前项目已经具备一个 HTML 预览页雏形，包含：

- 顶部版本栏
- 左侧文件栏
- 中间编辑区
- 右侧 Chat 区

当前主要问题不在“有没有区域”，而在于：

- 编辑器高亮和滚动行为不稳定
- 组件样式统一性不够
- 结构层和内容层还没有彻底分离
- 没有形成正式的开发执行与产品推进文档体系

---

## 5. 必须保留的内容

以下内容应优先保留，不应轻易删除：

- 顶部版本栏
- 左侧 Explorer
- 中间 Markdown 编辑器
- 右侧 AI Chat
- 文件与版本的基础组织方式
- 当前已有的日志类文件思路
- 冻结 / 归档 / diff 的文档理念
- 可复用的主题变量、边框、间距、圆角系统

原因：这些内容即使现在不完全成熟，后续也大概率用得上。

---

## 6. 需要改造的内容

以下内容要改造，但不删除其业务意义：

- 编辑区的选中行实现方式
- Chat 气泡的视觉风格
- 顶部版本栏的选中态
- 左侧文件栏的密度与层级
- 栏位高度统一
- 滚动后顶部渐变与高亮的稳定性
- 样式复用体系

---

## 7. 可暂缓删除的内容

以下内容当前可不做，但不应盲删：

- 终端
- Debug
- 输出面板
- 任务系统
- 扩展系统
- 复杂设置页
- 远程/容器/SSH 相关 UI
- 代码补全、Hover、minimap 等高级编辑特性

这些内容并不属于当前 MVP 的主路径，但后续产品演进时可能复用思路或局部能力。

## 8. 阶段划分

### 阶段 1：页面骨架统一

目标：把整体布局和样式体系统一起来。

完成标准：
- 四大区域结构稳定
- 颜色、边框、字号、间距统一
- 顶部版本栏、左侧栏、编辑区、Chat 区高度节奏一致

### 阶段 2：编辑器真实化

目标：把中间编辑区改造成真正可用的 Markdown 编辑器视觉与交互模型。

完成标准：
- 行号和文本对齐
- 当前行高亮稳定
- 滚动后状态不丢失
- 行高和光标位置一致

### 阶段 3：文档与版本治理

目标：让版本栏和文件栏真正承载版本、日志、差异、归档。

完成标准：
- 可切换版本
- 可查看变更
- 可定位历史
- 可区分冻结与当前版本

### 阶段 4：AI 工作流接入

目标：让 Chat 参与文档推进，而不是单纯聊天。

完成标准：
- 能围绕文档发问
- 能收敛版本差异
- 能推动确认与冻结

### 阶段 5：收敛与删减

目标：逐步清理长期不需要的内容。

完成标准：
- 不再出现冗余结构
- 不再出现重复样式
- 不再出现不必要的面板

---

## 9. 成功标准

当以下条件同时满足时，视为改造进入可用阶段：

- 页面像一个统一的工作台，而不是拼接页面
- 编辑器能够稳定表达当前行和滚动状态
- 版本栏、文件栏、Chat 具备明确职责
- 文档、日志、差异、归档有清晰位置
- 大多数样式通过公共变量或公共 class 复用
- 不再靠局部 hack 维持视觉效果
