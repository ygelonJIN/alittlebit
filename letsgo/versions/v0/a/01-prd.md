# PRD：{项目名称}

## 1. 项目背景与问题定义
- 核心痛点：现有桌面自动化工具存在明显缺陷：传统RPA（如UiPath）依赖规则驱动，缺乏AI智能匹配，跨环境适应性差；轻量RPA（如UI.Vision）单层匹配，可靠性不足；AI工作流（如Dify）仅处理文本/API，不涉及桌面GUI；Computer Use（如Claude）纯云端方案，延迟高、成本高、无本地快速路径；低代码平台（如n8n）不做桌面自动化。这些局限导致自动化效率低、成本高、跨机器不可靠。
- 核心价值：开发可视化无代码桌面自动化工具，允许每个执行节点自由配置降级策略栈（从本地快速匹配到云端AI兜底），实现省token、省时间、高可靠性的桌面自动化，填补市场空白。
## 2. 竞品与市场分析
- 市场现状：桌面自动化市场现有解决方案缺陷明显，缺乏集成AI级联降级的可视化工具。4级级联策略栈架构是市场空白。

### 竞品A：UiPath（传统RPA代表）
- 核心机制：基于规则和流程录制驱动的自动化，通过编辑操作序列实现任务执行。
- 优势：成熟稳定，企业级支持，生态丰富，广泛用于重复性流程自动化。
- 劣势：规则驱动，无AI智能匹配，跨环境适应性差，维护成本高，无法处理动态UI变化。

### 竞品B：Claude Computer Use（AI Computer Use代表）
- 核心机制：纯云端多模态AI模型直接理解屏幕内容并模拟操作，依赖API调用。
- 优势：智能识别UI元素，无需预定义规则，适应多种应用场景。
- 劣势：依赖网络，延迟高（2-5秒），成本高（token消耗），无本地快速路径，可靠性受限于云端推理。
## 3. 参考项目
### Open-Adapt
- 仓库地址：Open-AdaptAI/Open-Adapt (GitHub)
- 核心功能：AI录屏回放，通过记录用户屏幕操作实现自动化回放，支持失败重试。
- 可借鉴点：交互模式设计、录屏回放机制、失败重试逻辑，适用于学习自动化工作流的用户体验。
- 局限性：不专注于可视化管线编辑，无降级策略栈配置，缺乏跨环境智能匹配。

### Langflow
- 仓库地址：langflow-ai/langflow (GitHub)
- 核心功能：拖拽式AI管线构建工具，用于搭建大语言模型应用，支持节点自定义和画布交互。
- 可借鉴点：节点扩展机制、画布交互体验（如拖拽、连线、序列化）、管线JSON导出方式。
- 局限性：针对文本/API自动化，不涉及桌面GUI操作，无降级策略栈和图像匹配功能。
## 4. 核心场景
- 场景 1：用户需要自动化重复性桌面任务（如表单填写、数据采集），通过可视化画布拖拽节点（鼠标点击、键盘输入、截图等待）编排工作流。为每个目标点击节点配置降级策略栈（坐标回放→模板匹配→YOLO检测→OCR文字→云端API），确保在不同系统分辨率、缩放设置下可靠识别UI元素，并逐级降级匹配，平衡速度与准确性。
- 场景 2：用户调试自动化工作流，每步执行后自动截图对比变化，配置预期结果验证（如OCR识别成功文字），失败时暂停并展开调试面板，查看每步的匹配位置、置信度和截图，快速定位问题步骤。
