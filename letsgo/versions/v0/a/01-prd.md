# PRD：{项目名称}

## 1. 项目背景与问题定义
### 1.1 产品定义
可视化无代码桌面自动化工具。核心差异化：**每个执行节点内可自由配置降级策略栈**，本地快速 → 云端兜底，省 token、省时间、高可靠。

### 1.2 核心架构
```
可视化画布（React Flow）
    │
    ├── 节点类型
    │   ├── 鼠标操作（点击/拖拽/输入/滚动）
    │   ├── 键盘操作
    │   ├── 截图
    │   ├── 等待（延时/条件等待）
    │   ├── 判断（if/else）
    │   └── 循环
    │
    └── 每个「点击目标」节点内 N 道降级策略，独立配置
        ├── 策略1: 坐标回放        (最快, 零成本, 确定性)
        ├── 策略2: 模板匹配        (本地 OpenCV, 毫秒级)
        ├── 策略3: YOLO 特征检测   (本地推理, GPU 加速)
        ├── 策略4: OCR 文字定位   (本地, 识别文字内容)
        └── 策略5: 云端多模态模型  (API 兜底, 最慢最贵)
```
- 只用云端 API → 纯 API 模式
- 策略2+5 → 两道降级，大部分命中本地
- 全部五道 → 最大可靠
- **每个节点独立配置逐层启用/禁用 + 置信度阈值 + 超时策略**
## 2. 竞品与市场分析
### 2.1 市场现状
现有自动化方案存在明确缺陷：传统RPA规则僵化、维护成本高；AI工作流不涉及GUI；纯云端方案延迟高、成本高。市场缺乏一个将**本地快速执行**与**云端智能兜底**灵活结合的可视化无代码工具。

### 2.2 竞品对比
| 类型 | 产品 | 与本项目的差异 |
|------|------|----------------|
| 传统 RPA | UiPath, Automation Anywhere, Blue Prism | 规则驱动，无 AI 级联兜底 |
| 轻量 RPA | UI.Vision, OpenRPA, SikuliX | 单层匹配，无降级策略栈 |
| AI 工作流 | Dify, Coze, 扣子, Langflow | 只做文本/API，不碰桌面 GUI |
| Computer Use | Claude Computer Use, Open Interpreter | 纯云端，无本地快速路径 |
| 低代码 | n8n, Node-RED, ToolJet | 不做桌面自动化 |

**核心差异：本项目提出的4级级联策略栈架构是市场空白。**

## 4. 核心场景
### 4.1 MVP 路线与核心交付
```
Phase 1   Electron + React Flow 画布 + 坐标录制回放（策略1）+ PyAutoGUI+mss
Phase 2   + OpenCV 模板匹配（策略2）+ 截图框选存模板 + 二级降级
Phase 3   + OCR 文字定位（策略4）+ YOLOX 训练管线（策略3，跳过标注工具先用 labelImg）+ 级联引擎
Phase 4   + 云端多模态 API（策略5）+ 自建标注工具内嵌产品
```
**核心原则：先跑通 1→2→4（坐标 + 模板 + OCR），YOLO 和云端 API 放后面。**

### 4.2 执行引擎（DAG 调度器）
- **职责**：将画布产出的节点+连线图（JSON）执行起来：`画布 JSON → 拓扑排序 → 逐个节点执行 → 每节点内策略级联 → 结果回传`
- **架构**：前端（React）通过 `child_process` 调用 Python 执行引擎，Python 解析DAG并执行，通过 stdout JSON 实时回传进度。
