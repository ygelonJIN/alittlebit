# PRD：{项目名称}

## 1. 项目背景与问题定义
- 核心痛点：现有桌面自动化工具存在明显局限。传统 RPA (如 UiPath) 基于规则，无 AI 级联兜底机制，灵活性差；轻量 RPA (如 UI.Vision, SikuliX) 仅支持单层图像匹配，可靠性不足；AI 工作流平台 (如 Dify, Coze) 只处理文本与 API，不涉及桌面 GUI 自动化；Computer Use 类工具 (如 Claude Computer Use) 依赖纯云端 API，延迟高、成本高且缺乏本地快速执行路径。市场缺乏兼具可视化编排、AI 增强与多级本地化策略的方案。
- 核心价值：打造一款可视化无代码桌面自动化工具，其核心差异化在于每个执行节点内可自由配置降级策略栈。通过本地快速路径（如坐标回放、模板匹配）到云端多模态模型兜底的级联策略，实现省 Token、省时间、高可靠性的自动化执行，填补市场在这一细分领域的空白。
## 2. 竞品与市场分析
- 市场现状：4 级级联策略栈架构是市场空白。现有产品或侧重规则驱动的传统 RPA，或提供单层 AI 匹配，均无法在单个节点内实现灵活、可配置的多层次匹配与降级策略。

### 竞品A：传统 RPA (UiPath, Automation Anywhere, Blue Prism)
- 核心机制：基于预定义规则和脚本录制/回放，依赖控件树或坐标。
- 优势：流程稳定、企业级功能完善、生态成熟。
- 劣势：规则僵化，无 AI 级联兜底，面对动态界面或变化适应性差，无本地多策略降级能力。

### 竞品B：轻量 RPA (UI.Vision, OpenRPA, SikuliX)
- 核心机制：基于简单的图像模板匹配或基础脚本控制。
- 优势：轻量、开源、易于上手。
- 劣势：单层匹配，无降级策略，跨机器、跨分辨率场景可靠性低，调试和错误恢复能力弱。

### 竞品C：AI 工作流平台 (Dify, Coze, 扣子, Langflow)
- 核心机制：拖拽式构建 AI 处理管线，主要处理文本生成、API 调用、知识库检索等。
- 优势：擅长 AI 流程编排，节点灵活。
- 劣势：专注于文本与后端 API，不提供桌面 GUI 自动化控制能力，不涉及键鼠操作、截图与视觉匹配。

### 竞品D：Computer Use 类工具 (Claude Computer Use, Open Interpreter)
- 核心机制：通过云端多模态大模型直接理解屏幕截图并控制鼠标键盘。
- 优势：端到端 AI 驱动，理论上能处理复杂指令。
- 劣势：纯云端模式，延迟高、成本高、依赖网络；无本地快速执行路径，无法实现低成本、高可靠性的自动化。
## 3. 参考项目
### Open-Adapt
- 仓库地址：https://github.com/Open-AdaptAI/Open-Adapt
- 核心功能：AI 录屏回放，通过记录用户操作并学习进行自动化重放。
- 可借鉴点：其交互模式和失败重试逻辑，是最接近本产品形态的参考。
- 局限性：未采用多层级降级策略栈，自动化可靠性依赖于单一回放机制。

### Langflow
- 仓库地址：https://github.com/langflow-ai/langflow
- 核心功能：拖拽式搭建 AI 管线的可视化编辑器。
- 可借鉴点：成熟的节点扩展机制、画布交互模式及序列化方案。
- 局限性：专注于 AI 文本处理，不涉及桌面 GUI 操作。

### Rivet
- 仓库地址：https://github.com/Ironclad/rivet
- 核心功能：可视化 AI 管线编辑器，支持复杂的节点配置和嵌套。
- 可借鉴点：其节点内嵌套策略的思路，与本产品的“策略栈”概念高度一致。
- 局限性：面向 AI 推理流程，非桌面自动化专用。

### self-operating-computer
- 仓库地址：https://github.com/OthersideAI/self-operating-computer
- 核心功能：纯云端 GPT-4V 驱动的桌面自动化控制。
- 可借鉴点：证明了“看屏幕-操作”的市场需求真实存在，是云端策略（策略5）的单层版参考。
- 局限性：纯云端方案，成本高、延迟高，无本地快速路径和降级机制。
## 4. 核心场景
- 场景 1：用户需要自动化重复性的桌面操作（如批量处理表格、填写表单）。用户通过可视化画布，将每个操作步骤（如点击“同意”按钮、输入文本、选择下拉菜单）编排为节点，并为关键节点（如点击目标）配置多层降级策略栈（如先尝试坐标回放，失败则用本地模板匹配，再失败则调用云端API）。执行引擎按序运行管线，自动逐层尝试策略直至成功。
- 场景 2：用户需要在不同分辨率、缩放比例或主题模式的机器上运行同一自动化流程。通过多模板库策略，为同一目标元素在不同环境配置并存储多个模板，匹配时自动尝试，实现跨环境的可靠执行。
- 场景 3：用户训练自定义的 YOLO 模型以识别特定应用内的 UI 元素。在产品内截图、框选标注，配置训练参数（如迭代轮数、数据增强），一键启动训练。将训练好的模型作为策略3集成到节点中，用于高复杂度或动态界面的元素识别。
- 场景 4：用户在调试复杂工作流时需要定位失败节点。每一步执行前后自动截图并对比，高亮变化区域。用户可配置预期结果验证（如 OCR 查找“提交成功”文本）。验证失败时管线自动暂停，并展开调试面板，逐步回放显示每步的匹配位置、置信度和截图变化，帮助用户快速定位问题起始点。
- 场景 5：用户需调用私有或第三方云端多模态 API 作为最终兜底。在节点内自由配置 API endpoint、密钥、请求格式及提示词模板。产品负责自动将截图（可压缩或区域裁剪）发送至 API，解析返回的坐标，并支持级联多个 API 进行多数投票或按优先级选择结果。
